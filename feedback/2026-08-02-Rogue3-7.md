#### §4.4 An audit binding whose evidence is "this file contains the defect" cannot survive the fix, and the excuse rewrites history in place

- **Kind:** friction
- **Impact:** The audit-binding check pins a sha256 over every file a merged feedback report cites. When a finding is *about* a file's contents, fixing that file necessarily breaks the binding — the stronger the evidence, the more certain the future violation. Worse than the growth is the rewriting: excusing a binding whose file has changed *again* overwrites the existing entry's `observedSha256` **and its reason** in place, so the earlier rationale survives only in git history.
- **Expected:** Evidence bindings should distinguish "this file changed, so the report's claim may be stale" from "this file changed *because the report was acted on*", which is the success case rather than a violation. An excuse ledger should accumulate rationale, not replace it.
- **Observed:** This cycle broke four bindings in `feedback/audits/2026-08-02-Rogue3-5.audit.json` — the audit whose critic *verified* that `Visibility.fs` was dead, that the `Vec2.fs` comments disguised it, and that the scaffold map still advertised deleted files. Acting on those findings invalidated the record of them. No remedy is clean: `Visibility.fs` has no bytes to rebind to; rebinding `Vec2.fs` or `docs/scaffold-map.md` would pin bytes written after that critic reported and would erase the very text that *is* the evidence. All four were excused per the `7e71d71` precedent. The ledger went **48 → 51 entries**: three added (`Vec2.fs`, `Visibility.fs`, `docs/scaffold-map.md`) plus one pre-existing entry (`Rogue3.fsproj`, excused for M12 under `7e71d71`) whose digest and reason were rewritten in place, discarding M12's recorded rationale. So four bindings broke and only three entries appeared, which means the entry count structurally understates how many distinct events have excused a binding.
- **Evidence:** file:scripts/audit-binding-exceptions.json; command:git diff 6b4ed07 HEAD -- scripts/audit-binding-exceptions.json; file:feedback/audits/2026-08-02-Rogue3-5.audit.json; file:feedback/2026-08-02-Rogue3-3.md; command:python3 scripts/check-audit-bindings.py
- **Version:** n/a — repository-local tooling (`scripts/check-audit-bindings.py`), introduced by issue #15.
- **Owner:** EHotwagner/rogue3 — `scripts/check-audit-bindings.py` and the audit schema.
- **Recurrence:** seen again, narrowed. `feedback/2026-08-02-Rogue3-3.md` §7 already recorded this ledger as a standing workaround at 45 entries with the same permanence risk, and its §4.2 recorded that no rebind command exists, which is *why* the weak remedy is the only one with tooling. What is new here is the self-referential case — the file being fixed is the finding's own evidence, so the fix and the evidence cannot coexist — and the in-place rewriting of a prior entry's reason, neither of which is previously recorded.
- **Avoidable cost:** two `--grandfather` runs and a four-way excuse-versus-rebind judgement; no retries, no rework.
- **Disposition:** accepted for this cycle (the precedent is clear and was followed); recorded so the ledger's growth and its silent rewriting stay visible to whoever owns the schema.
