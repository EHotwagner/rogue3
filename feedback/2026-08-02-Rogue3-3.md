## §2 What worked

- Building `--selftest` into the checker **before** trusting its verdict caught a real defect in the checker's own ledger rebuild (§4.4). The cost was small and it fired on the first run. It also missed five further bypasses, so it is reported here as necessary rather than sufficient (§4.6).
- Commissioning a fresh-context adversarial reviewer that had never seen the design rationale was the highest-value step in the cycle. It did not merely read the code: it reconstructed every historical revision of all 23 files in the baseline ledger from git history and confirmed 23 of 23 pinned digests reproduce exactly under the new checker's rule — which independently establishes that the 45 excused bindings are genuine staleness and not a digest-rule divergence. No test in the suite could have shown that.
- Reproducing the tripwire against **genuinely bound files in the real tree** — appending two comment lines to `docs/reports/2026-08-01-roguelike-dungeon-crawler-completion.md` and `docs/roguelike-dungeon-crawler-roadmap.md`, then reverting — proved both failure paths (first-time staleness, and re-editing an already-excused file) on the exact data the check ships against, rather than on fixtures that could have been tuned to pass.
- Reading the authoritative digest rule out of `FeedbackReportTool.sha256Text` and reimplementing it exactly (CRLF/CR → LF, UTF-8, BOM-stripped) meant the new checker and the existing validator agree on what "fresh" means. Guessing here would have produced a check that is green while the validator is red.
- That agreement was then **measured rather than assumed**. Running `feedback-tool.fsx validate` against all thirteen report/audit pairs and counting its own `evidence digest is stale` lines gives 1, 8, 5, 3, 5, 5, 4, 3, 7, 11, 3, 1, 2 — **58**, per audit and in total exactly the new checker's raw count, with every audit non-zero. The 45 the checker reports is that same set after collapsing repeated citations of one file at one pin. Two independent implementations naming the same 58 rows is much better evidence than either alone.
- `scripts/fsgg-coord take --repo … --json` gated cleanly on exit code 0 and returned a converged claim in one call, with the claim marker already posted as an issue comment.

## §3 What did not

- The first attempt at the mandated identity command was refused by the harness before it ran (§4.3).
- The checker's own `--grandfather` was wrong on its second run and would have silently un-excused everything (§4.4). It was caught by the self-test in the same loop, before commit.
- The first design keyed an exception by `(audit, kind, locator)` only. That let a *rebound* audit silently inherit an exception written against the digest it no longer pins, and it collapsed two genuinely different pins of the same file into one row. Re-keyed on `(audit, kind, locator, boundSha256)`, which also de-duplicated the raw 58 stale digest rows down to 45 distinct bindings.
- The remedy the check names first — rebind the audit — turned out to have no command behind it (§4.2), which forced the entire pre-existing backlog into the exceptions path rather than the preferred one.
- The first version of the checker shipped to review with five false-negative bypasses (§4.6), and the 19-case self-test that had already caught one real defect found none of them. The author's confidence after §4.4 was not warranted, and this report would have overstated the result if the review had not happened.

## §4 Findings

#### §4.1 The feedback skill mints evidence digests and nothing ever re-checks them

- **Kind:** capability-gap
- **Impact:** Every merged cycle report in this repository currently fails its own evidence binding. At `1f19809` **13 of 13** audits carry at least one stale binding: **45 of 118** distinct file bindings are stale, 58 raw digest rows before de-duplicating repeated citations of the same file at the same pin. The 58 is confirmed independently by the skill's own validator, which reports exactly the same per-audit counts (§2). The rot is invisible, so a report's digests can be worthless for months while the report still reads as evidence-bound.
- **Expected:** A skill whose stated contract is "changing or deleting cited evidence invalidates a previously green audit" ships something that notices when that happens.
- **Observed:** `feedback-tool.fsx validate` checks an audit only when a human runs it against that one report. Nothing runs it again after merge, and nothing checks the other twelve. The consequence is already on the record twice — a documentation-only PR invalidated a merged report's binding and passed CI (`feedback/2026-08-01-Rogue3-12.md` §4.13), and a host acceptance gate published a verification that had not been performed (`feedback/2026-08-02-Rogue3.md` §4.1). Both were caught by luck. This cycle adds the missing tripwire locally, in `scripts/check-audit-bindings.py` plus a workflow that runs it on every pull request and on every push to `main`; the root cause remains upstream, because every generated product using this skill has the same hole.
- **Evidence:** command:python3 scripts/check-audit-bindings.py; command:dotnet fsi .agents/skills/fs-gg-feedback-report/scripts/feedback-tool.fsx -- validate feedback/2026-08-01-Rogue3-10.md --audit feedback/audits/2026-08-01-Rogue3-10.audit.json; file:scripts/check-audit-bindings.py; file:feedback/2026-08-01-Rogue3-12.md
- **Version:** FS.GG.SDD.Artifacts 0.32.0; no newer release available in this environment to re-verify
- **Owner:** FS-GG `fs-gg-feedback-report` skill — the audit contract in `SKILL.md` and the `feedback-tool.fsx` command surface
- **Recurrence:** seen again `feedback/2026-08-01-Rogue3-12.md` §4.13 and `feedback/2026-08-02-Rogue3.md` §4.1. Both are precedents for the *mechanism*; what is new here is the measurement at a second commit showing the staleness has grown (51 raw digests over 11-of-12 cycles at `97a352a`, 58 raw over 13-of-13 at `1f19809`) and the fact that it is now enforced rather than observed.
- **Avoidable cost:** none in this cycle; the cost is historical — one merged false verification claim and one corrective pull request, both already recorded
- **Disposition:** skill fix

#### §4.2 "Rebind the audit" is the recommended remedy and no command performs it

- **Kind:** capability-gap
- **Impact:** When a binding goes stale the correct fix is almost always to rebind that cycle's audit. There is no way to do it except hand-editing every `sha256` in the JSON, so the weaker fix — excusing it — is the only one with tooling behind it.
- **Expected:** A tool that computes and validates evidence digests can also recompute them for an existing audit.
- **Observed:** `feedback-tool.fsx` with no arguments prints exactly six subcommands: `checkpoint`, `activate`, `digest`, `validate`, `validate-checkpoints`, `validate-checkpoint-state`. `digest <text-file>` gives one hash for one file; joining 45 of those back into 13 audit documents by hand is the whole of "rebind". This directly shaped this cycle's output: the 45 pre-existing stale bindings were excused as a baseline rather than rebound, and the reason string recorded on all 45 says so.
- **Evidence:** command:dotnet fsi .agents/skills/fs-gg-feedback-report/scripts/feedback-tool.fsx --; file:.agents/skills/fs-gg-feedback-report/SKILL.md
- **Version:** FS.GG.SDD.Artifacts 0.32.0
- **Owner:** FS-GG `fs-gg-feedback-report` skill — `scripts/feedback-tool.fsx` subcommand surface
- **Recurrence:** new
- **Avoidable cost:** none measured this cycle, because the rebind was declined rather than attempted; the gap is what made declining it correct
- **Disposition:** issue

#### §4.3 The worker envelope's mandated first command cannot run in a worktree-isolated agent

- **Kind:** friction
- **Impact:** The first instruction a fan-out worker is given fails before it executes. A worker that reads the refusal as "identity could not be minted" would either stop, or improvise an id — and improvising an id is precisely the failure the claim protocol exists to prevent.
- **Expected:** `eval "$(scripts/fsgg-coord whoami --mint)"`, given as the literal first command, runs.
- **Observed:** In a worktree-isolated agent the harness refuses it unexecuted: *"this command is too complex to verify that it stays inside the worktree; break it into plain, separate commands."* Running `scripts/fsgg-coord whoami --mint` plainly and exporting `FSGG_WORKER` per invocation works and mints correctly — but the recovery is left to the worker to invent, and the engine's own hint ("eval this line, or export it, in EACH worker's shell") is the only thing pointing at it. The guard is broader than the `eval` form: the same cycle also had a plain `for` loop over `feedback/audits/*.audit.json` refused (moved into a script file and invoked as `sh <path>`) and a `gh pr comment --body "$(cat <<'EOF' …)"` heredoc refused (replaced with `--body-file`). Three refusals in one cycle. So the finding is not that one command was written badly; it is that the envelope's shell idioms and the isolation guard's accepted grammar were never reconciled.
- **Evidence:** command:scripts/fsgg-coord whoami --mint; file:feedback/checkpoints/item-15-audit-binding-tripwire.jsonl
- **Version:** n/a — harness behavior, not a package
- **Owner:** rogue3 worker prompt, and the `intra-repo-parallel-work` skill's minted-identity section
- **Recurrence:** new; no prior report in `feedback/` mentions the eval form or this refusal
- **Avoidable cost:** three refused commands and three retries
- **Disposition:** doc fix

#### §4.4 A gate that gates other people's work should gate itself first

- **Kind:** positive-pattern
- **Impact:** The self-test caught a defect in this cycle's own checker that would have made the whole tripwire useless on its second use, and caught it inside the first implementation loop rather than after merge.
- **Expected:** n/a — this records a pattern worth reusing.
- **Observed:** `--grandfather` rebuilt the exceptions ledger from the current *violations* only. On the second run the previously-excused bindings no longer count as violations, so they were dropped and an **empty** ledger was written — silently un-excusing everything, with exit code 0 and a success line. The failing case was labelled "the ledger is byte-stable across reruns"; nothing else in the suite would have caught it, because every other case ran `--grandfather` once. The fix seeds the rebuild from the still-valid exceptions before appending new violations. CI runs the suite *ahead* of the verdict, so a checker that has stopped detecting staleness cannot certify a commit as clean.
- **Evidence:** command:python3 scripts/check-audit-bindings.py --selftest; file:scripts/check-audit-bindings.py
- **Version:** n/a
- **Owner:** rogue3 `scripts/`; worth promoting into guidance for any repo-hardening check
- **Recurrence:** new
- **Avoidable cost:** none — the defect never left the working tree
- **Disposition:** accepted
- **Limit, and it is a large one:** this same 19-case suite then missed five further bypasses of exactly the kind it exists to prevent (§4.6). The pattern is necessary and demonstrably not sufficient; it should not be reported as though self-testing made the gate trustworthy.

#### §4.5 A board item's declared Paths cannot cover what the envelope requires the worker to write

- **Kind:** orchestration
- **Impact:** Disjoint-path fan-out is the mechanism that is supposed to keep concurrent workers off each other's files, and every worker is required to write outside its own declaration. What actually prevents collision in `feedback/` is the host handing each lane a pre-assigned report number — a separate mechanism the `Paths` field does not express.
- **Expected:** Either `Paths` covers everything the worker is required to write, or the envelope names the mandatory shared writes as an explicit exception with their own collision rule.
- **Observed:** Item 15 declares `Paths: .github/workflows/, scripts/`. The envelope simultaneously requires committing `feedback/checkpoints/<cycle-id>.jsonl`, `feedback/2026-08-02-Rogue3-3.md` and `feedback/audits/2026-08-02-Rogue3-3.audit.json` — three writes into `feedback/`, in a wave where every lane writes there. Nothing collided, and the path declaration contributed nothing to that outcome.
- **Evidence:** issue:EHotwagner/rogue3#15; file:feedback/checkpoints/item-15-audit-binding-tripwire.jsonl
- **Version:** n/a
- **Owner:** rogue3 board item template, and `.agents/skills/pnext-item` / `intra-repo-parallel-work` where `Paths` semantics are defined
- **Recurrence:** new
- **Avoidable cost:** none this cycle
- **Disposition:** issue

#### §4.6 The gate against silent failure was itself failing silently, in five ways, and only an adversarial reader found them

- **Kind:** defect
- **Impact:** Five false-negative paths in a check whose entire purpose is preventing false negatives. Any one of them would have let a stale binding pass with exit 0 and no trace, which is the precise failure this item was filed to end.
- **Expected:** A gate reports every input it cannot interpret. Skipping what it does not understand is indistinguishable from finding nothing wrong.
- **Observed:** (1) An unresolvable or absolute `file:` locator was skipped with `continue`, so changing `file:src/a.fs` to `file:/src/a.fs` hid a stale binding — the F# validator errors on exactly that input. (2) Containment was never enforced, so `file:../outside.txt` digested a file the repository does not contain and reported it **fresh**. (3) A non-UTF-8 bound file raised an uncaught `UnicodeDecodeError`, and because `--grandfather` also digests, the escape hatch crashed too — reachable today, since `feedback/2026-08-01-Rogue3-8-assets/` already holds PNGs. (4) A mangled audit bound nothing and passed: `"findings": {}` or a renamed `checkedEvidence` silently dropped every binding in it. (5) The documented exit code 2 was never returned; every input error exited 1, indistinguishable from "violations found". All five were reproduced against a copy of the real tree and are closed in `42ad8e3`; the self-test grew from 19 to 53 cases, and its digest claim is now anchored to a golden vector produced by the F# tool rather than to the checker itself.
- **Evidence:** command:python3 scripts/check-audit-bindings.py --selftest; issue:EHotwagner/rogue3#27; file:scripts/check-audit-bindings.py
- **Version:** n/a — defect in this cycle's own new code, fixed before merge
- **Owner:** rogue3 `scripts/`; the reusable lesson belongs wherever review expectations are written
- **Recurrence:** new. Note the *class* is not new: silently skipping an input you cannot interpret is the same shape as the original problem — nothing re-checked digests, so nothing reported them.
- **Avoidable cost:** one review round and roughly 35 minutes of rework, entirely before merge
- **Disposition:** product fix

## §7 Workarounds still in the tree

- `scripts/audit-binding-exceptions.json` — 45 baseline exceptions, all carrying one reason string that names `rogue3#15`, states that no record survives of which commit broke each binding, and explains why rebinding was declined. **Removal condition:** each entry disappears when its cycle's audit is rebound against the bytes that now exist, which needs the missing rebind command (§4.2). **Risk if permanent:** the ledger is the honest record that 45 merged evidence claims are unverified; left indefinitely it starts to read as a list of things that are fine. The design limits the decay — an exception is pinned to both the observed digest and the audit's pinned digest, so any further edit to those files, or any rebind of those audits, forces the entry back into review rather than letting it stand.

## §11 Falsifiable improvements

- **Ship the audit-binding check in the scaffold, not in one product.** Prevents §4.1 for every generated product rather than for this one. Owner: FS-GG `fs-gg-feedback-report`, template-produced files. Acceptance: a freshly scaffolded product contains a check that fails when a file cited by an audit under `feedback/audits/` changes, and the scaffold's own CI runs it.
- **Add `feedback-tool.fsx rebind <report> --audit <audit>`.** Prevents §4.2 and drains §7. Owner: FS-GG `fs-gg-feedback-report`, `scripts/feedback-tool.fsx`. Acceptance: running it against an audit with stale `file:` digests rewrites exactly those `sha256` fields, leaves every other byte of the audit unchanged, and makes `validate --audit` pass; running it against a fresh audit is a no-op.
- **Replace the literal `eval "$(…)"` first command with the two-step form.** Prevents §4.3. Owner: rogue3 worker prompt and `intra-repo-parallel-work`. Acceptance: a worktree-isolated worker mints an identity with no refused command.
- **State in the board item template that `feedback/` is written by every worker regardless of `Paths`, and that per-lane filenames are the collision rule.** Prevents §4.5's silent contradiction. Owner: rogue3 board item template. Acceptance: an item's declared `Paths` plus the named feedback exception together cover every file a compliant worker writes.
- **Require an independent adversarial reviewer for any change that is itself a gate.** Prevents §4.6. Owner: rogue3 worker envelope / `pnext-item` review step. Acceptance: for a PR that adds or modifies a CI gate, the review explicitly enumerates the inputs the gate cannot interpret and states what it does with each; "skips it" is a finding, not an answer.
