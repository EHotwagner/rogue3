#### §4.1 InteractiveAppHost has no native gamepad polling seam

- **Kind:** capability-gap
- **Impact:** Hollow Depths has a deterministic and replayable gamepad snapshot model, but the pinned live shell cannot produce native left-stick/right-stick/trigger polls; this is release-significant for first-class twin-stick control.
- **Expected:** The upstream Hollow Depths specification §3 requires the input subscription to capture a gamepad snapshot once per frame, including independent left/right analog sticks and trigger state.
- **Observed:** `InteractiveAppHost` exposes `MapKey`, `MapPointer: PointerInteraction -> 'msg option`, and `Tick`, but no native gamepad poll/source. Product code can consume `InputChanged`, yet the host has no supported producer for it.

- **Avoidable cost:** one explicit scope decision and one release integration obligation
- **Disposition:** issue

#### §4.2 Lower-viewer continuous pointer pacing is not exposed by the Controls interaction fallback

- **Kind:** capability-gap
- **Impact:** Mouse aim updates on hover-entry, primary-button, drag, click, and scroll coordinates, but an unpressed move remaining over the same control may produce no `PointerInteraction`; continuous mouse aim is therefore not established through the shipped Controls composition.
- **Expected:** The lower viewer's default `CoalesceLatestPerFrame` policy should remain available when `InteractiveAppHost` adapts onto it, while Controls click/hover/focus behavior remains lossless.
- **Observed:** `InteractiveViewerHost.MapPointer` accepts every `ViewerPointerInput` and its current API exposes explicit pacing policies and counters. `InteractiveAppHost.MapPointer` instead receives only consumer-facing `PointerInteraction` values; that union has hover transitions and drag moves but no bare same-control move. The product did not bypass Controls with a raw wrapper.
- **Evidence:** file:docs/api-surface/SkiaViewer/SkiaViewer.fsi;file:docs/api-surface/Controls.Elmish/ControlsElmish.fsi;file:docs/api-surface/Controls/Pointer.fsi;issue:FS-GG/FS.GG.Rendering#1040;issue:FS-GG/FS.GG.Rendering#1044;command:dotnet package search FS.GG.UI.Controls.Elmish --exact-match --source https://api.nuget.org/v3/index.json --format json

## §6 Doc-versus-behavior contradictions

- The upstream Hollow Depths specification says the input subscription polls gamepad state once per frame, while the pinned `InteractiveAppHost` API has no gamepad field (§4.1). Product code exposes the pure snapshot seam but cannot complete that host subscription on this package surface.
- The lower SkiaViewer API documents coalesced continuous pointer sampling, while the Controls `InteractiveAppHost` fallback receives only the narrower `PointerInteraction` taxonomy (§4.2). The uncertainty is Controls composition, not absence of the already-shipped lower-viewer pacing feature.

## §7 Workarounds still in the tree

- `InputChanged` is the clean pure boundary, not a fake poll, but native gamepad producers must call it once a host seam exists. Removal condition: the pinned live shell host provides a supported gamepad source.
- `pointerInteractionToMsg` maps every coordinate-bearing Controls interaction currently available, but mouse aim updates continuously only while the adapter emits such interactions. Removal condition: `InteractiveAppHost` exposes or composes the lower coalesced `ViewerPointerInput` seam without bypassing Controls.
