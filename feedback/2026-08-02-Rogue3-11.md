## §11 Falsifiable improvements

- **Give the validator the gate's excuse route.** Owner: FS-GG `fs-gg-feedback-report`,
  `FeedbackReportTool.fs` plus a ledger analogous to `scripts/audit-binding-exceptions.json`.
  Prevents §4.2 and §4.3. Acceptance: with no rebinding of any merged audit, `validate` exits 0 for
  every report/audit pair in this repository — 20 of 20, against 2 of 20 today — and editing
  `.github/workflows/audit-bindings.yml` or `build.fsx` does not change that count.
- **Declare the bindable-path rule once and have both tools read it.** Owner: FS-GG
  `fs-gg-feedback-report`, shared with this repo's `scripts/check-audit-bindings.py`. Prevents the
  drift #40 is an instance of. Acceptance: exactly one declaration exists; a mutation that changes it
  makes both tools' selftests fail. Interim, cheaper acceptance: `exemption()` carries a back-pointer
  to the validator, so the side that is actually edited warns its maintainer.
- **Require a ported test suite to port its narrowness cases.** Owner: FS-GG `pnext-item`
  `references/independent-review.md`. Prevents §4.8. Acceptance: when a rule is reimplemented from a
  reference implementation, the review checklist names the reference's own test cases and the diff
  shows each one either ported or explicitly declined.
- **Resolve `Paths:` to the file carrying the logic at triage time.** Owner: FS-GG `padd-item` /
  `work-board` triage. Prevents §4.6. Acceptance: measured over a week, the count of items whose
  first worker edit requires a prior `widen` is zero.
- **State whether a cycle's own artifacts still validate, and how many did before.** Owner: FS-GG
  `work-roadmap` / `work-board` `references/feedback-contract.md`. Prevents a cycle reporting success
  against an untested premise, as this one nearly did. Acceptance: the contract requires a
  before/after validator tally over all pairs, and the host's acceptance step reproduces it.
- **Document the kit-editing contract in the skill that owns the kit.** Owner: FS-GG
  `fs-gg-feedback-report` `SKILL.md`. Prevents §4.5's near-miss. Acceptance: the skill states the
  byte-identical mirror requirement, both manifest pin locations, and the provenance record, so a
  worker editing a kit file needs no out-of-band message.
