## §4 Findings

#### §4.1 The merge gate rewrites its own tracked evidence artifact into a smaller, false state and exits 0

- **Kind:** defect
- **Impact:** Every worker who follows the documented instructions — run the full gate, then stage — commits an artifact asserting that evidence disappeared. A reviewer reading a green `Verify` has no reason to open it. This repo has already published one false verification by trusting a gate's exit status (`feedback/2026-08-02-Rogue3.md` §4.1); this is the same class one layer down, with the gate itself as the falsifier.
- **Expected:** A gate either leaves a tracked evidence artifact byte-identical, or fails loudly naming what it could not evaluate. It does not silently publish a smaller number.
- **Observed:** On a clean worktree at `7d9d442`, `./fake.sh -t Verify` exited 0, printed `Verify completed for generated rogue3`, and rewrote `readiness/evidence-graph.md` from `- readiness files present: 102` to `93`. **Ten** entries dropped and **one** was gained. All ten dropped entries are untracked: five fsgg-sdd outputs under `readiness/014-m13-room-transition-pickups-world-state/` (`analysis.json`, `governance-handoff.json`, `ship.json`, `verify.json`, `work-model.json`), which only the checkout that ran the lifecycle holds, and five of the seven `readiness/logs/*.txt` — `TemplateDrift.txt` and `GeneratedGuidanceCheck.txt` survive because #34 made them real steps that run *before* the graph; `Dev.txt` is never written by `Verify` at all since #34 removed it; the other four are written after. The gained entry, `readiness/014-.../critic-history.md`, is **tracked**, so the committed artifact was already wrong before this cycle. `readiness/evidence-audit.md` is tracked and rewritten by the same run but records only a verdict and a node count, so it is checkout-stable and came back byte-identical every time.
- **Evidence:** command:./fake.sh -t Verify; command:git check-ignore -v readiness/logs/Test.txt; file:build.fsx; file:.gitignore; issue:EHotwagner/rogue3#26
- **Version:** FS.GG.UI 0.21.1 (`Directory.Packages.props`), engine `FS.GG.UI.Build` resolved from that property. Reproduced at `7d9d442` and again at `3913c26`; no newer engine available in this workspace.
- **Owner:** FS.GG.UI.Build — the `GeneratedRunner` EvidenceGraph emitter, which enumerates a partially-untracked input tree and publishes the result unconditionally. Secondarily EHotwagner/rogue3 `build.fsx`, which is where a generated product can refuse the result.
- **Recurrence:** seen again — first `feedback/2026-08-02-Rogue3-5.md` §4.3 (as `67 → 58`, nine entries, since corrected), then `feedback/2026-08-02-Rogue3-4.md`, which additionally observed that a working `-t Run` target would perturb the same artifact further; `issue:EHotwagner/rogue3#26`.
- **Avoidable cost:** four full gate runs (~4 min each) to measure and re-measure, plus a `git checkout` after each to undo the falsified artifact. Prior cycles paid the same cost and reverted by hand.
- **Disposition:** product fix — `build.fsx` now applies a set-based superset publication rule: an emitted graph may overwrite the published one only if it sensed at least as much, otherwise the previous bytes are restored by file copy and every missing input is named. `FSGG_EVIDENCE_GRAPH_PUBLISH=1` publishes deliberately from a full tree. The emitter-side root cause remains with the engine.

## §7 Workarounds still in the tree

- **`FSGG_EVIDENCE_GRAPH_PUBLISH`** (`build.fsx`). The deliberate-publication escape hatch. Removable once the emitter stops enumerating untracked inputs, or once the roll-up stops being tracked (#26's remaining root-cause options). Risk if permanent: it becomes the normal way to update the graph, and someone runs it from an incomplete tree "because that is how you refresh it" — which is the original defect with an extra step. Mitigated by the diagnostic naming every missing input first.
- **The restored graph is deliberately stale** (`build.fsx`). On a refusal the previous file is restored whole, so its counters and node table are last-complete-emission values. This is the intended trade — a stale complete record over a fresh falsified one — and the diagnostic says so, but nothing marks the file itself as not-refreshed-by-this-run.
- **Five excuse-ledger entries for `build.fsx`** (`scripts/audit-binding-exceptions.json`). Not removable under the current design; each is retired only when the citing audit is rebound, which the repo discourages. Grows by roughly one entry per audit per cycle that touches a bound file. See #53.
