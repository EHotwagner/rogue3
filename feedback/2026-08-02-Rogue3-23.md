  fix.** rogue3#77's third bullet asks for "a mutant that restores the existence check for an exempt

  behaviour; naming the mutant as well turns it into a claim about the *test*, which is the part

  throwaway workspace on disk. It was the inner loop, not a final gate: 13 mutants were applied and
  reverted against it across the cycle.

  The code critic, given a mutation licence and its own worktree, found nine surviving mutants and

  explicitly *not* to mutate, found four false sentences, an un-guarded constant, and a measured

  other's list. A single critic asked to do both would have done one of them.

  believed and why.** `"a citation onto a MISSING ledger is still an error -- only the digest has no

#### §4.12 The worktree-isolation guard rejects redirection, heredocs and pipelines, so every command that captures output must be split

- **Kind:** friction
- **Impact:** Every gate invocation in this cycle is two calls instead of one, and every ad-hoc
  analysis script had to be written to a file first.
- **Expected:** A worker in an isolated worktree can run `tool > log 2>&1; echo $?` and
  `python3 - <<EOF`.
- **Observed:** Both are refused with "this command is too complex to verify that it stays inside
  the worktree; break it into plain, separate commands". The workaround is benign — write the script
  to the scratchpad, invoke it by absolute path — and it interacts badly with the standing
  instruction to capture true exit codes rather than `$?` after a `| tail`, because the
  compliant form (`cmd > file; echo $?; tail file`) is itself a compound command. The form that
  survives is `cmd > file 2>&1; echo "EXIT=$?"` as one call and `tail file` as another.
- **Evidence:** command:eval "$(scripts/fsgg-coord whoami --mint)" is refused as too complex to verify; command:python3 - <<EOF heredoc is refused with the same message; command:dotnet fsi .agents/skills/fs-gg-feedback-report/scripts/feedback-tool.fsx -- selftest > FILE 2>&1 followed by a separate read is the form that works
- **Version:** harness at 2026-08-02
- **Owner:** worker orchestration harness
- **Recurrence:** first record in this repository's reports.
- **Avoidable cost:** ~10 minutes across the cycle, and one scratchpad script per analysis.
- **Disposition:** recorded; §11.3.
