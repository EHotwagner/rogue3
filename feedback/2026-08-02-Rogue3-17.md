  found four false statements in the draft of this report.

  `FAIL`-grepping guard had been replaced by an ok-count guard. That record is what made it obvious
  that the ok-count guard belonged to the same doomed family rather than being a one-off bug.

## §4 Findings

#### §4.1 `Path.GetTempPath()` honours `$TMPDIR`, so "evaluate it from somewhere else" is defeatable from the environment

- **Kind:** defect
- **Impact:** A hardening defence in the merge gate was a silent no-op under one environment
  setting. With `TMPDIR` pointing at the repository, a tree carrying both a cwd-keyed check
  exemption and real kit drift went from exit 1 to exit 0 — the gate green on a drifted tree.
- **Expected:** relocating the process out of the repository makes `root = currentDirectory`
  unsatisfiable however the comparison is normalised, which is what the defence's own comment
  claimed.
- **Observed:** `Path.GetTempPath()` returns `$TMPDIR` when set, so the relocation relocated to the
  repository root and the exemption fired exactly as before.
- **Evidence:** command:on a git archive export with templateDriftViolations prefixed by if root = Directory.GetCurrentDirectory() then [] else and a line appended to the manifest-pinned kit file .agents/skills/fs-gg-ai/SKILL.md, dotnet fsi build.fsx -t SelfTest exits 1 with the relocation defence present and exits 0 when TMPDIR is set to the export root, so the defence is a no-op under that one environment setting, and after the fix the same mutant exits 1 both with and without TMPDIR while an unmutated tree under TMPDIR set to its own root still exits 0; file:build.fsx; issue:EHotwagner/rogue3#71
- **Version:** .NET 10.0.302. Defect present in PR #71 under review; closed before merge. Fixed
  state is `3cd9ab5`, where the relocation creates its own subdirectory and fails closed if the
  working directory did not actually change, with the measurement recorded inline.
- **Owner:** EHotwagner/rogue3 — `build.fsx`; generalises to any FS.GG scaffold code that treats the
  system temp directory as a location outside the workspace
- **Recurrence:** new
- **Avoidable cost:** one blocking review round; the defence had already shipped in the PR
- **Disposition:** product fix — landed in `3cd9ab5`

## §11 Falsifiable improvements

1. **Generated self-test targets should emit a structured result artifact from the start.** Prevents
   §4.6. Owner: EHotwagner/fs-gg scaffolding, generated `build.fsx` template. Acceptance: a freshly
   scaffolded product's self-test target writes a machine-readable result carrying at least a verdict
   and a case tally, its generated CI guard asserts those fields, and no generated CI guard parses
   the target's stdout.
2. **A mutation-sweep protocol skill.** Prevents §4.3, the mis-targeted-anchor cost in §8, and the
   unverifiability recorded in §1. Owner: EHotwagner/fs-gg skills. Acceptance: a skill exists that
   requires discarding non-compiling mutants, requires the harness's own summary line before scoring
   a row, requires before/after comparison over a fixed mutant set, and requires the mutant
   inventory to be committed as an artifact; a worker following it produces a sweep a reader can
   recompute.
3. **A quantified hardening claim must be re-derived or struck when its pinned base stops being the
   base.** Prevents §4.7. Owner: EHotwagner/rogue3 issue conventions. Acceptance: when a merge
   changes a file an open issue quotes figures for, the issue is either updated or its figures are
   explicitly marked superseded; an implementer who re-derives at the pinned commit reproduces the
   number, and is told when that commit is no longer current.
4. **The audit-binding ledger should not hold whole-file digests over files that change every
   cycle.** Prevents §4.5 and the growth in §7. Owner: EHotwagner/rogue3,
   `scripts/check-audit-bindings.py`. Acceptance: two workers editing different regions of
   `build.fsx` concurrently do not contend on a shared ledger file.
5. **The `--grandfather` remedy text should say the append must be the cycle's last edit.** Prevents
   §4.8. Owner: EHotwagner/rogue3, `scripts/check-audit-bindings.py`. Acceptance: the message printed
   on a stale binding states that the excuse pins one digest and will go stale on the next edit to
   the same file; a worker who follows it does not need a second `--grandfather` run.
