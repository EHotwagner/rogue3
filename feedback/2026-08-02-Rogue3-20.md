## §2 What worked

  gate — twice.** The ledger went from one shared file to the union of a directory of files, and
  then the whole remedy was rewritten again after the critics. All 72 pre-existing cases needed only
  mechanical call-site edits across both rewrites. The suite went 72 → 130 checks and still runs in
  under a second, so it was the inner loop rather than a final gate.
- **Proving a coordination claim instead of arguing it.** The acceptance criterion is about what two
  concurrent workers do, which reads like something you can only negotiate. Three throwaway git
  repositories holding just `check-audit-bindings.py` and one seeded audit turn it into commands
  with exit codes, and running the *same* harness against `715bef9`, against the first candidate,
  and against the second makes each claim a diff rather than an assertion (§4.1, §4.6).

  found the same blocking defect by completely different routes — one by reading the F# validator's
  existence check and reasoning about union states, one by building a 73-mutant matrix and a git
  scenario — and each found things the other did not. Neither rubric alone would have produced the
  shipped design.
- **The comment culture in `check-audit-bindings.py`.** The module docstring already recorded *why*
  the ledger was exempt from binding and why the obvious second exemption was wrong, with the

  path to the ledger directory without re-litigating it — and it is also what made the design

  cost is that a cycle whose implementation lands in three passes re-stales its own excuse twice —

  violations, dropping the entries in it that now excuse nothing, so a re-run after a further edit

  remedy text the tool prints now says to run it **last**, which is the folklore the prior cycles
  negotiated, made explicit at the point of failure.
- **Evidence:** file:scripts/check-audit-bindings.py; command:python3 scripts/check-audit-bindings.py --selftest exits 0 with the cases "re-excusing replaces this cycle's entry rather than accumulating" and "an unchanged re-run carries every entry forward verbatim"
