## §4 Findings

#### §4.1 The product's structural fingerprint is built on a formatter that truncates after 100 elements

- **Kind:** defect
- **Impact:** Every workload authorship digest since M2, and every runner-issued journey receipt since M3, could not distinguish two model values that differ only past the 100th element of any collection. The maximum-content fixture the mechanism exists to bind holds 600 particles, 120 enemy bullets and 40 shots, so the majority of its declared scale sat inside the blind spot. A reviewer acknowledging a digest was acknowledging less than the artifact claimed.
- **Expected:** A definition digest and a receipt fingerprint bind the complete structural model, as `feedback/2026-08-01-Rogue3-3.md` §4.1 states the M2 repair intended, and as the pre-repair in-source comment asserted: "Model is a closed structural record: %A covers every field recursively".
- **Observed:** `modelDefinitionFingerprint` and `messageDefinitionFingerprint` both digested `sprintf "%A"` output. `%A` applies a default print length of 100 to collections, so `sprintf "%A" [1..600]` and `sprintf "%A" ([1..599] @ [999])` are the identical 401-character string. `messageDefinitionFingerprint` additionally built one entry per sampled frame for workloads that run 120 to 720 frames, so it fingerprinted only the first 100 frames of the route. Both now use a product-owned canonical structural encoder with no length limit, and a regression test pins the difference. The formatter is not scaffolded: `git show cd0028f:src/Rogue3/PerformanceEvidence.fs` contains no `sprintf "%A"`, and it enters at the M2 repair.
- **Evidence:** command:git show ea0dfc1:src/Rogue3/PerformanceEvidence.fs; command:git show cd0028f:src/Rogue3/PerformanceEvidence.fs; file:src/Rogue3/PerformanceEvidence.fs; file:src/Rogue3/Determinism.fs; file:tests/Rogue3.Tests/M10AcceptanceDeterminismTests.fs
- **Version:** reproduced at .NET 10.0.10 with FS.GG.UI.Build 0.21.1, FS.GG.Contracts 7.5.2 and FS.GG.Game.Harness 0.12.0; the defect is in product-authored source, so there is no upstream release to re-verify against
- **Owner:** Rogue3, `src/Rogue3/PerformanceEvidence.fs` model and message definition fingerprints plus the journey-receipt fingerprint binding. The reusable FS.GG-facing lesson is separated into §4.2.
- **Recurrence:** new; introduced by the repair recorded in `feedback/2026-08-01-Rogue3-3.md` §4.1 and extended by `feedback/2026-08-01-Rogue3-4.md` §4.2. Those two are source-closure findings, so this is a defect created by their remedy rather than a recurrence of them. No issue reference exists because this repository's tracker is empty.
- **Avoidable cost:** all seven authored workload digests and three UI-route digests re-derived and copied, plus one product encoder written to replace the formatter
- **Disposition:** product fix

#### §4.2 The determinism guidance never names an encoding or its truncation limit

- **Kind:** documentation
- **Impact:** Two independent authors in this product reached for `sprintf "%A"` as a determinism or fingerprint encoding: the M2 performance repair, and the stashed prior-art replay draft this milestone reviewed. Both were wrong in the same way, which points at the guidance rather than at either author.
- **Expected:** Guidance that tells an author to compare serialized values for determinism either names an encoding safe for that claim or warns about the print-length limit of the obvious one.
- **Observed:** `fs-gg-game-core` covers seeded generators and split sub-streams thoroughly and then defers the question, pointing at the seeded-generation section of `fs-gg-testing` for byte-identical fixtures. `fs-gg-testing` gives the right instruction — "Assert on the serialized fixture, not the live value ... Byte-identity on the serialized form is the strongest cheap determinism check there is" — but assumes a product already owns a `serialize` for save slots. Neither skill says what to do when the value to compare is the whole simulation model, and neither mentions that `%A`, the obvious substitute, stops after 100 elements. The prior-art draft documented `%A` as its "stable F# structural encoding" on that basis.
- **Evidence:** file:.agents/skills/fs-gg-game-core/SKILL.md; file:.agents/skills/fs-gg-testing/SKILL.md; command:git stash show -p stash@{0} --include-untracked
- **Version:** skills as materialized at FS.GG.SDD.Artifacts 0.32.0; upstream skill sources were not available for re-verification
- **Owner:** FS.GG game-core and testing skills, the determinism-encoding step between "assert on the serialized form" and having a serializer
- **Recurrence:** new
- **Avoidable cost:** one replaced prior-art encoding and one measurement round to establish the limit
- **Disposition:** skill fix

#### §4.7 The committed performance evidence artifact is not reproducible from unchanged sources

- **Kind:** quality-gap
- **Impact:** Two runs of the same command on the same commit produce different committed evidence, so a reviewer cannot diff a candidate's evidence against its baseline to see what the candidate changed. Every regeneration also dirties the working tree, which makes "regenerate evidence" and "record a real change" indistinguishable in `git status`.
- **Expected:** An evidence artifact that is committed and reviewed is either reproducible from its sources, or separates its reproducible declarations from its measured samples so the former can be diffed.
- **Observed:** Running `./fake.sh build -t Verify` from a clean tree with no source edit leaves `readiness/performance-evidence.json` and `readiness/m7-ui-performance.json` modified. Every authored `definitionDigest` is stable across the run, which is the part that gates review. What moves falls into two distinct causes. The first is inherent measurement variance: `p50Ms`, `p95Ms`, `p99Ms` and `allocatedBytes`. The second is identity churn: `compositionAuthority` carries the freshly built assembly's module version id and therefore changes on every rebuild, taking all seven `receiptDigest` values, the critic block's `inputDigest` and the UI `artifactDigest` with it. Only the second is fixable by stabilizing anything. The source comment states the volatile build identity is deliberately kept in the critic digest and deliberately excluded from the source-declaration digest, so the churn is by design; the consequence for reviewability is not addressed.
- **Evidence:** command:./fake.sh build -t Verify; command:git diff --stat readiness/performance-evidence.json readiness/m7-ui-performance.json; file:src/Rogue3/PerformanceEvidence.fs
- **Version:** FS.GG.Game.Harness 0.12.0, FS.GG.Contracts 7.5.2; upstream was not available to check whether a newer harness stabilizes the composition authority
- **Owner:** FS.GG.Game.Harness journey-receipt composition authority for the identity churn, and the Rogue3 evidence emitter for committing measured samples beside authored declarations. The split is inferred from where each changing value is produced, not from an upstream source that could be read here.
- **Recurrence:** new. This repository's issue tracker is enabled and empty, and no row was filed this cycle, so the routing recorded here is the only artifact carrying it.
- **Avoidable cost:** one restore of two regenerated artifacts per verification round; four such rounds this cycle
- **Disposition:** issue
