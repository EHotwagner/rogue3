## §2 What worked

- `FS.GG.Audio.Host` reported the defect precisely and unprompted. The line `FS.GG.Audio.Host: track 'title-theme' did not resolve to an asset — AssetResolver.ResolveTrack returned None, so every play of it is silent` names the id, the exact resolver function, the ownership boundary (FR-005) and the two plausible causes. A one-command launch was enough to reproduce the milestone and to give an exact before-string to hold the fix against.
- `FS.GG.Audio.Host.Wav.tryParse` and the `Wav.FormatPcm` literal are public, so the guard applies the **same** structural test the device backend applies before upload rather than a lookalike. `Backend.kindOf` likewise let the evidence command report `DeviceBacked` instead of assuming a device, which is what stops a playback claim from being vacuous on a machine with no sound card.
- Putting the cue id declaration in a module that opens nothing let one file serve the compiled product, a `dotnet fsi` generator and the test at once. That is what made "derived from source" achievable rather than aspirational, and it caught a mistake the same hour (§4.5).
- Mutation-checking the gate against the live tree turned "the test would fail" from an argument into four observations: delete an asset, truncate an asset to zero bytes, add an inline literal, revert the cue map to its interpolated form. The fourth of those only exists because a critic ran it first and it **passed** (§4.7).

## §3 What did not

- The guard shipped with the milestone's own defect class inside it, and two of its arms could not fail (§4.7). Found by critics, not by the author, and not by a fully green 206-test suite.
- The author's hand count of the cue set was wrong in `plan.md` and `clarifications.md`: eleven tracks written as ten, twenty-nine ids as twenty-eight. It never reached a test or an asset because the generator loops over the declaration (§4.5).
- Every performance percentile quoted in the first candidate came from a run whose artifact was never committed — the numbers were read from a scratch file, then a different run was committed. Corrected to the committed artifact.
- Obtaining the product's player-launch `status=` line failed after five strategies (§4.4), and the first framing of why was wrong: an in-product close route exists and is already wired.
- `fsgg-sdd plan --accept-upstream` discarded a seven-entry authored section, twice (§4.2). Anticipated from two prior reports, so `plan.md` was copied first each time and each loss cost one restore.
- `fsgg-sdd evidence` blocked on citing a committed `.wav`, with a headline message asserting the file does not exist (§4.3).

#### §4.4 The product's already-wired graceful close has no trigger automation can reach

- **Kind:** capability-gap
- **Impact:** The player-launch outcome record — the one line that answers "did the shipped launch open a window and present a frame" — cannot be obtained by a script on this host, so a milestone about audibility proved its launch claim from the **absence** of a diagnostic plus a separate, non-audio capture.
- **Expected:** A scripted launch can obtain the product's own launch outcome.
- **Observed:** The first framing of this was too broad and the report's critic corrected it. A `status=` line **is** obtainable here: `--launch-evidence` runs `Viewer.runBounded`, self-closes, and reports `window-opened=true first-frame-presented=True renderer-mode=OpenGL`. What that route cannot do is discharge an audio claim — `EvidenceCommands.fs:757-765` renders a static scene offscreen with no Elmish host, no `PlayAudio` sink and no `OpenAlBackend`. The *player* launch prints its record only after `ControlsElmish.runInteractiveAppWithWindowBehaviorAndAudio` returns, and it returns only when its window closes. The graceful close is already wired exactly as `fs-gg-skiaviewer` prescribes: `GameShell.fs:176` maps `Quit` to `Effect.ExitRequested`, and `EvidenceCommands.fs:413` maps that to `ViewerEffect.CloseWindow`. The missing piece is a **trigger**: `Quit` is dispatched only from the main menu's `"exit"` button `OnClick`, and `EscapePressed` at `MainMenu` is a documented no-op, so reaching it needs a pointer click. This host cannot deliver one — the window is a native Wayland surface under KWin that `xdotool` cannot see, a KWin script matching on caption and then `pid` closed nothing, `SIGINT`/`SIGTERM` kill before the `printfn` (exit 124, 143), and an `Xvfb` run does produce a real X11 window but segfaults in software-GL teardown on both `windowclose` and `windowkill` (exit 139).
- **Evidence:** file:readiness/013-m12-audio-assets/launch-evidence.md; file:readiness/013-m12-audio-assets/launch-mode-evidence.txt; file:src/Rogue3/EvidenceCommands.fs; file:src/Rogue3/GameShell.fs
- **Version:** FS.GG.UI 0.21.1 viewer, .NET SDK 10.0.302, KWin Wayland session. Not re-verified on an X11 session, which this host does not offer.
- **Owner:** Rogue3 — `src/Rogue3/GameShell.fs` and `src/Rogue3/WindowOptions.fs` own the trigger; the close itself needs no change.
- **Recurrence:** new as stated. Related but distinct prior art in `feedback/2026-08-02-Rogue3.md`: §4.4 is the `Run` target stalling, §9 records the `libdecor-gtk` failure when forcing the X11 backend, and §12's runtime-playtest row records that the host "obtained no screenshot of a live window". That report also records the same launch printing `window-opened=true` with exit 0 — obtained by a human closing the window, which is the one route automation lacks, and which is why the gap is about the trigger rather than the record.
- **Avoidable cost:** roughly twenty-five minutes across five strategies, plus a wrong first framing in the artifacts that a critic had to correct.
- **Disposition:** product fix

#### §4.6 Committed binary assets stayed reviewable because the code that produces them is compiled product source

- **Kind:** positive-pattern
- **Impact:** 2,311,678 bytes of binary entered a repository with no LFS without becoming opaque, and the reproduction claim was checked by CI on a second platform rather than asserted.
- **Expected:** n/a — this records a composition worth keeping.
- **Observed:** The synthesis lives in `src/Rogue3/AudioSynthesis.fs` and the generator script is a thin driver over it, so the test calls the same function the generator calls and asserts the committed bytes are identical. That converts "these binaries are reproducible" from a claim into an assertion, and makes a hand-edited asset a red suite. It only works because the synthesis avoids libm: `sin`, `exp`, `log`, `pow` and `tanh` would each be a platform-dependent result inside a byte-exact comparison, so the file uses a polynomial sine, polynomial envelopes, an integer LCG and a cubic soft clip, computing every sample from `+ - * / abs floor` alone. The check then passed on `ubuntu-latest` CI against bytes generated on Arch, and an independent critic regenerated all twenty-nine files and got no diff. The cost is stated rather than glossed: PCM compresses poorly, so the pack goes from 1.63 MiB to roughly 3.6 MiB.
- **Evidence:** file:src/Rogue3/AudioSynthesis.fs; file:tests/Rogue3.Tests/M12AudioAssetTests.fs; command:gh pr checks 25 --repo EHotwagner/rogue3
- **Version:** .NET SDK 10.0.302 on Arch Linux and on `ubuntu-latest`
- **Owner:** Rogue3, `src/Rogue3/AudioSynthesis.fs`; the pattern is general enough for the `fs-gg-audio` skill.
- **Recurrence:** new
- **Avoidable cost:** none
- **Disposition:** accepted

## §11 Falsifiable improvements

Would have prevented §4.1 and made M12 unnecessary.
- **Make the evidence stage's artifact diagnostic tell the truth.** When a cited artifact exists but is not UTF-8 decodable, report that as the headline rather than `artifactNotFound`, and state whether citing binaries is supported. Owner: FS-GG/FS.GG.SDD evidence stage. Acceptance: citing a `.wav` or `.png` produces a diagnostic whose first line does not assert the file is absent. Second cycle requesting it (§4.3).
- **Preserve or name the reclaimed plan section.** Owner: FS-GG/FS.GG.SDD plan stage. Acceptance: authored content under `## Performance Intent` survives `fsgg-sdd plan`, or the run emits a diagnostic naming that section. Duplicate of `feedback/2026-08-01-Rogue3-11.md` §4.5 and `-12` §4.6; recorded as recurrence, not as a new proposal (§4.2).
- **Give `Quit` a trigger automation can reach.** The close effect is already wired; add a bounded launch flag that dispatches `GameShell.Quit` after N seconds, or a keyboard route to it from the main menu.
