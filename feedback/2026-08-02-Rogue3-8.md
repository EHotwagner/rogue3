## §2 What worked

- **Mutation testing paid for itself four times over, and the payment was concentrated in exactly the code the change is about.** The code critic ran 38 mutations and 19 passed green. Three of those were in the two derivations this whole item exists to introduce: `actorRadius` could be pinned to a constant `64.0` — the exact unspawnable shape the item's own commit message says storing the field enabled — and either `HitPoints > 0.0` filter behind the `EnemyDied` count could be deleted, silencing all death audio, with 231/231 still green. A refactor's most-owed guard is on the thing it replaced, and nothing but mutation found that the guard was absent. Reusable rule: **when a change replaces a stored value with a derivation, mutate the derivation to a constant before claiming the change is safe.**
- **Two critics, two different classes of finding, and neither would have found the other's.** The code critic built both revisions and ran identical scenarios against each, which is the only way the bomb/burst timing shift was ever going to surface. The evidence critic re-ran the merge gate from a clean `git archive` export and read the evidence entries against the tree, which is the only way four entries asserting a gate that had not been run were going to surface. Both independently found the shop regression, from opposite directions — one by probing the reducer, one by diffing the deleted assertions. Fifth consecutive cycle in this repository where a second critic found what the first accepted.
- **The item's own premise was re-derived rather than trusted, and it was wrong in a useful way.** The issue asserts `Enemies`/`M5Enemies` are two representations of one fact. They are not quite: the legacy record carried `Velocity`, `LastContactTick` and `HitFlashTicks` that `EnemyActor` had nowhere to put, and `Radius`/`ContactDamage` that are total functions of `Kind`. Reading that distinction before writing anything is what produced the "three move, two do not" decision instead of a lossy delete.
- **Sequencing a contended file with its holder cost one message and saved the whole known-defect route.** `scripts/audit-binding-exceptions.json` collided with `EHotwagner/rogue3#38`. Rather than racing it, the two workers agreed an order on the board. #38's merged fix exempts the ledger from its own scan, so the hand-prune-plus-rebind route that #38 documents as "the only route to green" — which requires editing another cycle's merged audit — never had to be walked. `--grandfather` converged in one pass, 61 → 69 entries, and both gate commands exit 0.
- **The exact-equality cost-driver gate is the reason the fixture problems were findable at all.** `MaximumExpected` is compared for equality in `maximum-content`, not as a ceiling. Every one of §4.1 and §4.2 surfaced as a red evidence run with a number attached, not as a judgement call. A ceiling would have absorbed all of it silently.

#### §4.1 A maximum-content workload can be exactly green while measuring a population the product cannot produce

- **Kind:** quality-gap
- **Impact:** `collision.combat-candidates` stood at an exactly-verified 2520 for the whole of M13. That number was produced by 30 legacy enemies with a hand-written 64-unit radius, zero contact damage and 10000 hit points, co-located on the player — a shape no floor can spawn on any of the three axes. Replacing them with the roster actors the game ships collapsed the driver to **310**. Recovering a defensible number required restating *both* of the legacy fixture's devices on spawnable actors (cluster position and 10000 hit points), and the honest ceiling is **2100**: the workload now measures strictly less than the number it certified for a milestone. Five full Release evidence runs, ~25 minutes, were spent characterising one driver.

#### §4.2 The workload measuring the shot pass-through filter could not exercise it, because the two rect shapes could never be equal

- **Kind:** defect
- **Impact:** `Model.stepInput` subtracts non-shot-blocking obstacles from the player's collider set with `Set.contains`, comparing rects built by `toSimRect obstacle.Position 40.0 40.0`. The `maximum-content` fixture wrote eight **32×32** rects at hand-written coordinates straight into the legacy `Obstacles` field. A 32×32 rect can never equal a 40×40 one, so the subtraction removed nothing and `shotWalls` always equalled the whole collider list. `collision.shot-wall-queries` certified 820 on a filter that had never run in the workload built to measure it.
- **Expected:** A structural cost driver over a filtered set should exercise the filter. A fixture that populates the *input* of a derivation by writing its *output* directly cannot.
- **Observed:** With the collider set derived from `M5Obstacles`, the filter finally subtracts the `Pit` — which blocks movement but not shots — and the driver moves 820 → 740. Arithmetic verified independently by a critic: `740 = 2×(40 shots × 7 shot-blocking rects) + 2×6×(8 movement-blocking rects + 7 wall slabs)`. The old field was the mechanism: it let a fixture bypass the derivation entirely, which is the same "two representations, one of them wrong" shape the board item is about, one layer down in the evidence.
- **Evidence:** file:src/Rogue3/Model.fs; file:src/Rogue3/PerformanceEvidence.fs; file:readiness/performance-evidence.json; command:git show d8d0024:src/Rogue3/PerformanceEvidence.fs
- **Version:** n/a — product-local, present since the field was introduced.
- **Owner:** EHotwagner/rogue3 — `src/Rogue3/PerformanceEvidence.fs` fixture authorship; root cause is the pre-M5 free-floating rect field this item removed.
- **Recurrence:** new as a finding; it is the same root cause as `EHotwagner/rogue3#20` itself, observed in the evidence layer rather than the model.
- **Avoidable cost:** none as rework — the finding fell out of the removal — but a driver stood at a number that had never exercised its filter for a whole milestone.
- **Disposition:** product fix (the fixture now places nine real obstacles, eight blocking and seven shot-blocking) plus a regression test added after a critic showed the existing assertion could not fail

Owner: FS-GG performance-evidence surface (`pnext-item/references/performance-first.md` `PERF-PLAN`, plus a declaration field). - **Fix the `fsgg-sdd plan` Performance Intent round-trip.** Prevents §4.9, now on its fifth recorded cycle across four reports. Owner: FS-GG SDD CLI — `fsgg-sdd plan`. Acceptance: author a `## Performance Intent` section with `PI-001`…`PI-007`, run `fsgg-sdd plan` twice, and require the section to be byte-identical after both runs.
