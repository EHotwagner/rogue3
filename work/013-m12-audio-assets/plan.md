## Plan Scope
- Work item 013-m12-audio-assets is planned from the current specification, clarification, and checklist facts.
- Requirement count: 10.
- Clarification decision count: 10.
- Checklist result count: 11.
- The defect is an absence, not a wrong behaviour. `AudioCues.fs` requests the right ids at the right transitions, `Program.fs` hands the right resolver to `OpenAlBackend.create`, and the host reports each miss on stderr exactly as its contract says it will. What is missing is the twenty-nine files, a declaration the assets can be derived from, and a gate that reds when one goes missing. So the plan adds two product source files, one committed asset set, one generator, one evidence command and one test file — and changes `AudioCues.fs` only to stop holding literals.
- The second row is the load-bearing one. M8 shipped `shipReady` with 12/12 obligations while every cue was silent, because the obligations were about what the product *requests*. This plan's gate is about what the product can *resolve*, through the same resolver value the production launch uses, and it derives its obligation from the same declaration the cue map does — so it cannot pass while the product is silent, and it cannot drift from the cue map without failing.

## Plan Decisions
- PD-001 [AC-001] [FR-001] [DEC-001] complete: Add `src/Rogue3/AudioCueIds.fs`, a dependency-free `module Rogue3.AudioCueIds` compiled first in `Rogue3.fsproj`. It exports one named `string` per cue id, `floorThemeCount`, `floorTheme : int -> string`, and `sounds`/`tracks` lists built from those same values. It opens nothing, so `dotnet fsi` can `#load` it directly and the product compiles it unchanged — one declaration reaching all three consumers.
- PD-002 [AC-001] [FR-001] [DEC-001] complete: Rewrite the cue-id half of `src/Rogue3/AudioCues.fs` to build every `SoundId`/`TrackId` from `AudioCueIds`. `sfx` takes an id value rather than a string, `forAudioEvent`, `cueForPickup`, `doorAndBossCues`, `directEventCues`, `m5ShopPickupCues` and `track` reference the exported names, and no cue id literal remains outside the file's own doc comments. Cue *values* — the volumes, the ordering, the diff-derived transitions — are untouched, so every M8 expectation holds byte for byte.
- PD-003 [AC-006] [FR-006] [DEC-002] complete: `AudioCueIds.floorTheme` clamps its argument into `[1, floorThemeCount]` with `floorThemeCount = 6`, matching the six floors the product's own `FloorIndex=6` victory condition defines. `AudioCues.track` calls it instead of interpolating, so the parameterized family is total by construction: no integer, reachable or not, can name a track the declaration does not export.
- PD-004 [AC-007] [FR-007] [DEC-003] complete: Add `src/Rogue3/AudioSynthesis.fs`, a BCL-only pure module compiled after `AudioCueIds.fs`. `AudioSynthesis.render : string -> byte[]` returns the complete 16-bit mono 22050 Hz PCM WAV bytes for a cue id — a deterministic composition of oscillators, an ADSR-shaped envelope, seeded value noise and, for the eleven tracks, a short looping arpeggio over a per-track scale. It is a total function over the declared ids and raises on an unknown id, so a typo cannot silently synthesize an empty file.
- PD-005 [AC-007] [FR-007] [DEC-003] complete: Add `scripts/generate-audio-assets.fsx`, a thin driver that `#load`s `AudioCueIds.fs` and `AudioSynthesis.fs`, creates `assets/audio/`, writes `<id>.wav` for every declared id, and reports the file count and total bytes. It contains no cue id and no synthesis: it is a loop over the declaration, so it cannot drift.
- PD-006 [AC-007] [FR-007] [DEC-003] complete: Commit the twenty-nine `.wav` files under `assets/audio/`, 2,311,678 bytes in total: eighteen sfx of 4 KB to 62 KB (0.09 s to 1.40 s; the two boss stings are the ones over a second), and eleven four-second loops of 176,444 bytes each. That takes a 1.63 MiB pack to roughly 3.6 MiB, about 2.2x, which is stated in the clarifications rather than glossed. The guard proves the committed bytes equal `AudioSynthesis.render id` for every id, so the binaries are reviewable by re-derivation rather than by inspection, and a hand-edited asset reds the suite.
- PD-007 [AC-008] [FR-008] [DEC-009] complete: Widen `AudioCues.tryReadAsset` to probe two roots in order — the process working directory, then `AppContext.BaseDirectory` — and add `<Content Include="assets/audio/*.wav" CopyToOutputDirectory="PreserveNewest">` items to `src/Rogue3/Rogue3.fsproj` and `tests/Rogue3.Tests/Rogue3.Tests.fsproj` with a `Link` that preserves the `assets/audio/` shape. `assetRoot` keeps its literal value and meaning. Without this the product is audible only from one working directory and the guard would be testing the repository tree rather than the built product.
- PD-008 [AC-002] [FR-002] [AC-003] [FR-003] [DEC-004] [DEC-006] complete: Add `tests/Rogue3.Tests/M12AudioAssetTests.fs`, compiled after `M11PlayabilityLegibilityTests.fs`. Its first scenario enumerates `AudioCueIds.sounds` and `AudioCueIds.tracks`, resolves each through `Rogue3.AudioCues.resolver` — the same value bound in `Program.fs` — and asserts `Some` bytes that `FS.GG.Audio.Host.Wav.tryParse` accepts with `FormatTag = Wav.FormatPcm`, `Channels = 1`, `BitsPerSample = 16` and a non-empty `Data`. The failure message names every id that failed and why.
- PD-009 [AC-004] [FR-004] [DEC-004] complete: The guard proves its own discriminating power: the same predicate applied to `SoundId "m12-id-with-no-asset"` and `TrackId "m12-id-with-no-asset"` must fail, and the scenario asserts that it does. A gate that cannot be shown to fail is the defect class this milestone exists to close, so the demonstration is part of the gate rather than a comment about it.
- PD-010 [AC-005] [FR-005] [DEC-007] complete: The guard scans **every** `.fs` under `src/Rogue3/` for drift, not `AudioCues.fs` alone: it locates the tree from the test assembly by walking up to the repository root, fails if it cannot find it, asserts it found a populated source directory containing `AudioCues.fs`, strips `//` comment text outside string literals line by line, and then requires three empty sets. (1) No plain `SoundId "..."`, `TrackId "..."` or `sfx "..."` literal ANYWHERE — not merely no undeclared one, because `sfx "shot-fire"` is drift by any other name: the id would then live in two places and could diverge. (2) No INTERPOLATED form `SoundId $"..."` etc. A value that is not known until it runs cannot be compared with the declaration at all, so it is rejected rather than checked — and this is the hole the first draft had: `TrackId $"floor-{max 1 index}-theme"` is not a plain literal, so a `SoundId|TrackId|sfx\s+"..."` scan reported clean over the one construction that produces six of the twenty-nine ids. (3) No `sprintf`/`String.Format` construction applied to `SoundId`/`TrackId`/`sfx`, for the same reason. Because the expected result is three empty sets, the scanner is proved before its report is trusted: the scenario first runs the identical scanner over a five-line fixture holding one live `sfx` literal, one commented-out literal, one literal followed by a trailing comment containing another, the real doc-comment line from `AudioCues.fs`, and one interpolated track id, and asserts it extracts exactly the two live ids and exactly the one interpolated id. It also asserts `AudioCues.fs` still contains `AudioCueIds.`, so a rewrite that abandoned the declaration cannot pass by having no literals. Comment stripping is required rather than tidy: the file's own doc comments contain `SoundId "save"`, `TrackId "theme"` and the M12 note that quotes these very forms, none of which the product requests.
- PD-011 [AC-007] [FR-007] [DEC-003] complete: The guard asserts reproducibility as a test rather than a claim — for every declared id, the bytes on disk equal `AudioSynthesis.render id` — and asserts the declaration itself is well formed: twenty-nine distinct ids, no duplicates across the sound and track sets, and every id a filesystem-safe lowercase slug. It also closes AC-007's "and no others" in the direction nothing enforced: `assets/audio/` must contain exactly the declared file set and no other file, so a cue renamed without deleting its old asset reds the suite instead of shipping an orphan in every build output.
- PD-012 [AC-006] [FR-006] [DEC-002] complete: Totality is proved at BOTH ends. The declaration end: `AudioCueIds.floorTheme` is evaluated across `-3 .. 12` and every result must be in `AudioCueIds.tracks`. The shipped end: `AudioCues.replaceWithCurrentMusic` — the public cue map the shell calls on a run transition — is driven at every index in `-2 .. 9` and every track it requests must be declared, with floor 1, floor 6 and an index past the last floor pinned exactly. The second half is not redundant: reverting `AudioCues.track` to its pre-M12 interpolated form left every other scenario green, because the declaration was still total and the scripted sequence only reaches floors one and two. A declaration nothing consults proves nothing.
- PD-013 [AC-009] [FR-009] [DEC-005] complete: Add an `--audio-asset-evidence [path]` command to `EvidenceCommands.fs`. It constructs the backend through the exact `FS.GG.Audio.Host.OpenAlBackend.create Rogue3.AudioCues.resolver` expression `Program.fs:134` uses, reports `Backend.kindOf`, and writes one line per declared id with its resolution, byte length, and parsed channels/bits/rate, plus a summary and an explicit `unresolved=` count. It runs from the shipped binary, so it reports what the shipped binary can reach. What it does NOT do is play anything, so no buffer is uploaded to the device: `backend-kind` and `resolved=` are two independent facts from one command, and `AssetDiagnostics.UploadRejected` exists precisely because a device can still refuse bytes that parse. That limit is disclosed in the evidence rather than left for a reader to infer.
- PD-014 [AC-009] [FR-009] [DEC-005] complete: Launch the shipped build the way a player does — `dotnet run --project src/Rogue3` — capture its combined output verbatim and commit BOTH captures, before and after, as `readiness/013-m12-audio-assets/launch-output-before.txt` and `-after.txt`, so the comparison is inspectable rather than quoted. The obligation fails on any `FS.GG.Audio.Host: ... did not resolve to an asset` line. Window and first-frame evidence comes from a separate `--launch-evidence` run, which self-closes and does print a `status=` line on this host but carries no audio sink; the player-launch `status=` line specifically is unobtainable here because the already-wired `GameShell.Quit -> ExitRequested -> ViewerEffect.CloseWindow` route has no trigger but a pointer click. What cannot be proved from this host — that a speaker physically moved, and that the device accepted the bytes — is disclosed in evidence rather than asserted.
